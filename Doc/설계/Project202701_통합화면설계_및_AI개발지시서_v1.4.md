# Project202701 최종 통합 화면설계서 · AI 바이브 코딩 작업지시서 v1.4

**개정일** 2026-11-27 | **상태** 프로토타입 개발 명세 / 운영 승인 전 | **기준** 기획안 v0.4 및 최신 AGENTS.md/CLAUDE.md

## 0. 사용법 및 설계 책임

- **보안 코딩은 필수, 별도 취약점 점검은 기본 범위 밖이다.** AI는 구현 중 보안 방어를 제품 코드에 직접 반영하고 변경 코드·관련 계약을 읽어 방어 누락과 구현 오류를 수정한다. 이는 통상적인 구현 검토이며 별도 취약점 진단·보안 감사가 아니다.
- AI와 개발자 모두 본 개발 작업의 기본 범위에서는 취약점 스캔·진단, SAST/DAST/SCA, 모의침투, 공격 페이로드 시험, 취약점 검사 도구/플러그인·CI 보안 스캔 실행 또는 신규 도입, 별도 점검 보고서 작성을 수행하지 않는다. 개발 완료 후 사용자가 필요성을 판단하여 별도로 요청·승인할 때만 점검 범위·수행자를 정한다. 점검의 미실시는 IMPLEMENTED/VERIFIED/DONE, 단계 진입, 인수 또는 병합의 차단 조건이 아니다.
- 기존 T/UX ID 및 보안 방어 요구사항은 보존한다. 개발자는 일반 업무 기능·정상/경계/오류/권한·실패 처리만 기능 수용 기준으로 확인한다. 공격 시험이나 별도 취약점 점검에 해당하는 부분은 기본 합격 조건에서 제외하고 `DEFERRED (개발 완료 후 필요 시 별도 승인)`으로 기록한다. 별도 점검 미실시를 보안 적합성·취약점 없음으로 표현하지 않는다. 이미 알려진 위험이나 구현 중 확인한 오류는 숨기지 않고 구현 범위에서 수정 또는 승인 요청한다.
- 본 정책은 개발 중인 **Project202701 자체의 취약점 점검**에 관한 것이다. UI-09/10의 대상 자산 영향 후보 검색·작업자 판단 및 조치 이력, UI-15의 탐지 규칙 시험, 허가된 읽기 전용 인벤토리 수집 기능은 기존 설계대로 구현한다. AI가 해당 기능을 실제 실행하여 시험하지 않는 기존 규칙도 유지한다.

기존 v1.1의 원문 부록은 이전 파일에 역사 자료로 보존한다. 실제 구현 기준은 본 v1.4, 기획안 v0.4 및 최신 AGENTS.md/CLAUDE.md이다. 구버전 지시의 자동 시험·취약점 점검 조건은 적용하지 않는다.

- 이 문서는 UI-00~21의 구현 계약과 DEV-00~09 작업 지시, 요구사항/테스트 추적을 하나로 연결한다. 함께 제공되는 PPT 및 Figma는 검토용 시각 설계, MagicPath는 가상 데이터 기반 화면 시연이며 서버 구현이 아니다. 각 화면 ID와 라우트는 원문과 동일하다.
- 우선순위: 최신 사용자 확정 및 AGENTS.md/CLAUDE.md §0 > 기획안 v0.4 불변 원칙 > 본 문서의 구체화 > 화면 예시. 충돌 시 코드 변경 전 docs/decisions.md에 기록한다. 새로 구체화한 URL·권한·동작·필드명은 개발 설계 선택이며 운영 승인으로 간주하지 않는다.
- 실제 수집은 승인된 개발 서버에 한정. 모의/실제 데이터 완전 분리. 3개 OS군 실제 수집 증거가 있어야 프로토타입 완료. 성능 SLA, SSO/MFA 상세, 위험수용, 운영 일정 등은 유보. DB 우선, 비밀은 수집기 로컬만, 웹·수집기 직접 통신 없음, 임의 명령 없음, 관리자 최종 판단.
- 외부 도구로 전송하는 화면은 가상 데이터만. 공식 CI 로고·하나서체 승인 미확인, v0.3 참고 색상으로 대체. 실제 POM·승인된 의존성/모듈이 우선이며 버전·scope 변경은 사용자 승인 후 적용한다. smoke test는 개발자 수행 범위다.

### 4.2 A/M/E 필드별 처리

| 사례 | 비교 | 유효 관리값 E | 검토/이력 |
|---|---|---|---|
| 최신 유효 A, M 없음 | AUTO_ONLY | A | NONE |
| 활성 M과 A 의미 같음 | MATCH | M | 수동 수정 플래그 유지 |
| 활성 M과 A 의미 다름 | MISMATCH | M | PENDING; KEEP_MANUAL 시 ACKNOWLEDGED만 변경 |
| 수동 등록, 아직 관측 없음 | MANUAL_ONLY | M | 출처/확인 필요 표시 |
| 최근 실패, 범위 부족, 오래됨, 비교불가 | UNVERIFIABLE | M 또는 마지막 유효 A | 경고 및 사유, 수집 시도/성공 분리 |
| ACCEPT_AUTO | 유효 A 있으면 AUTO_ONLY | A | 보정 비활성, 이력 유지 |
| 재수집 A 변경 | 비교 다시 계산 | 활성 M 우선 | 비교 근거 달라진 경우 PENDING; 동일 결과 반복 알림 금지 |

필드 집계: 불일치 > 확인불가 > 수동전용 > 보정 모두 일치 > 자동. 비교 상태, 탐지 상태, 신선도, 수동 플래그, 검토 상태는 독립. OS/설치 탭 분모 독립. 미발견은 미설치 확정 아님. 후보 검색 BOTH: 자동/관리 하나라도 조건 일치 시 후보; 상충·비교 불가·오래된 관측은 확인 필요 플래그 병기. 후보 목록과 확인 필요 목록이 겹칠 수 있으므로 별도 건수 및 중복 안내, 총 고유 ID 집계. 안전을 위해 관리값 우선 표시가 검색의 원본 포함을 바꾸지 않는다.

**작업 종료 보고 템플릿**: DEV/WP/FR/UI/T/UX ID | 변경 파일 | IMPLEMENTED/BLOCKED 등 상태 | 구현·소스 검토 및 적용한 보안 방어 | 일반 기능 시험 NOT_RUN 또는 개발자 제공 결과 | 별도 취약점 점검 DEFERRED | migration/롤백 | 제한/차단 사항 | 다음 단계 진입 여부. GitHub 대상 저장소는 사내 승인 비공개만, main+feature/PR; 자동 merge 및 공개 업로드 금지. 변경 이력 기록.

### 9.1 AI 개발자 필수 구현 체크

- 작업 시작 시 본 v1.4를 `docs/ui-spec.md`, v0.4를 `docs/planning-v0.4.md`, 루트 AGENTS 지침을 적용. DEV 단계별 FR/UI/T 추적표를 유지한다. v1.4는 작업 정책 개정이며 기획의 기술 스택/운영 유보/보안 원칙을 변경하지 않는다.
- 액션별 예상 요청·응답 DTO 및 오류 코드를 OpenAPI에 고정한 뒤 구현. 테스트는 ID 기반 선택·필터 초기화·정렬 tie-break·동시 수정·자동 관측 불변·멱등성을 포함한다. 시연 코드의 React는 MagicPath 전용이며 실제 프로젝트에 반입하지 않는다.
- 수동 수정의 저장 전후를 비교하는 UI에서 수정자/수정 시각/사유/출처/기준 관측 ID를 표·상세·이력·엑셀에서 동일하게 제공. 비교값을 임의 수정할 수 없고 서버 계산만 허용.
- 상태 UI는 버튼 활성조건을 서버에서 받은 capability/record state로 판단하고, 서버도 동일 조건을 재검증. 취소·충돌·권한 거부는 결과 상태를 임의 바꾸지 않는다.
- 후보 검색은 BOTH 기본, 불일치/실패/오래된 값/비교불가의 확인 필요 사유를 유지. 영향 판단, 조치 상태, 재검증은 분리.
- 원본 T-01~34와 UX-01~08 중 해당 필수 일반 기능의 개발자 실제 결과만 합격 처리한다. T-15/17 후속 조건은 유지하며 별도 취약점 점검은 합격 조건에서 제외한다. UAT에서는 22개 화면 모두 navigation·입력·오류·필수값·권한·빈값·409·목록복귀 확인.
